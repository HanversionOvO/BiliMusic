# 分 P 播放回归检查

## 自动检查

使用 Node.js 22.18+ 或 Node.js 24：

```sh
node --experimental-strip-types --test tests/playbackTimeline.test.ts
npm run build
```

## 手动复现与检查

音源：https://www.bilibili.com/video/BV1q4FTeBEMj/ ，100 P，总长 419:02。

1. 播放合集，将进度拖至 209:31；应定位到 P48 的 2:01，继续播放而不是停在 P1 结尾。
2. 暂停后跳转到同一位置，应保持暂停；再点击播放应从该位置续播。
3. 在 P1 末尾播放，应自动进入 P2，合集进度继续超过 228 秒；关闭“自动播放”也应完成当前合集的各分 P。
4. 保存中间位置后重启，应恢复到正确分 P；快速连续跳转或切歌时，旧请求不能覆盖最新音源。
5. 分别检查短音频拖动、单曲循环整个合集、合集末尾进入队列下一首，以及拖动取消后保持原位置。

## 已有验证记录

上述播放实现已在 Windows Electron 中验证：暂停时拖至 209:31，实际音频局部位置为 121 秒，合集位置为 12571 秒；P1 结束后加载 P2 并继续推进。对应实现亦用于独立 Android 适配版本；该适配另行贡献，本修复不引入 Android 依赖。

根因：每个 CID 都有独立音频源，原实现把合集总时间写给第一个 CID 的音频元素。修复维护全局进度与分 P 局部进度的映射，并在单 P 的 ended 事件中衔接下一 P。进度条拖动时只预览，松手后提交一次跳转。
